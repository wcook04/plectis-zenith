# A working investigation interface: qualification and diagnostic campaign

This is a prospective engineering and mechanism protocol. It uses the existing
native SQLite, LRU and UTF-8 contracts to find out whether a model can deliver
distinct legal experiments and whether measured feedback changes its next
experiment. It does **not** test transfer to a new software mechanism, acquired
memory, or an improved learning algorithm. The earlier Ling campaign and all
PROGRESS return cases are exposed development evidence, not a confirmation
population. The machine-readable staging plan is
`work/progress-assimilation-20261014/campaign-plan.json` (local work material).

## Why this campaign comes first

The previous twelve model-written investigators consumed 62 slots: 51
duplicates, seven new valid measurements, three execution errors and one stop.
None obtained a second distinct measurement. Fixed testing reached 239/288
confirmation answers, while the ordinary generated investigator and unchanged
parent reached 216/288. Those 288 answers came from six parent episodes and
three authored mechanisms. In addition, every faulty parent episode already
failed a public example. A repair-only arm is necessary to learn what any new
probe contributes beyond asking the repair model to use known evidence.

## Freeze before inference

Freeze the source snapshot, task-generator version, exact native contracts,
public examples, fixed query pack, source bindings, panel seeds, parent count,
model ID, pinned endpoint, reasoning setting, response schema, per-call output
limit, arm order, budgets and analysis script. Use the repository's budgeted
provider and current verified endpoint metadata; the historic Ling price is
not a current tariff. Use a recent eligible Chinese-developed model, with no
unverified fallback. Keep dependent calls in order, at most one call on the
pinned endpoint at once. Each stage has a separate $0.60 hard ceiling, which
is a maximum authorization for its run, not a bill forecast. No paid inference
is part of this protocol document.

Use one fresh parent per task and keep that parent byte-identical across arms.
Generate a three-parent qualification set, one per contract, with a fixed seed.
Keep it out of the later diagnostic. Generate a disjoint twelve-parent
diagnostic set, four per contract, with its own seed. Freeze both dataset files
and panel assignments before the first paid call. A later dataset seed is a
fresh within-family sample, not an independent mechanism. Do not choose a
favourable parent subset after seeing its model output.

## Arms and delivery contract

Every arm starts from the same parent and public evidence. All six receive one
whole-program repair call with the same backend and output allowance; the
only prompt difference is the evidence actually obtained by its investigation.
The unchanged parent is the no-repair reference.

| Arm | Investigation allowance | Question answered |
|---|---|---|
| `repair_only` | No new probe or investigator call | Does another repair call already suffice? |
| `fixed` | Eight predeclared legal queries; no investigator call | How far does a competent simple tester get? |
| `ordinary` | One generated Python selector call, up to eight slots | Does the legacy compiled interface deliver? |
| `direct_batch` | One direct JSON call proposing up to eight queries; host owns the cursor | Can a finite plan deliver distinct legal probes? |
| `direct_adaptive` | Up to two direct JSON calls, at most four proposals per turn; second sees first-turn receipts | Does measured feedback help choose later probes? |
| `direct_masked` | Same allowance; second sees previous query identities and JSON delivery errors, but no native or parent outcomes or query-legality errors | What changes when outcome feedback is withheld? |

The host validates legality, deduplicates against public examples and earlier
proposals, measures the native source, separately executes the parent, and
stops at the first verified discrepancy or explicit stop. A duplicate or bad
proposal consumes a proposal slot and any model call, but no additional native
measurement. A native decoder error under a legal query is an observation; an
investigator exception is not a parent defect. Keep the stage that produced
every error in a typed receipt delivered to repair. The direct arms must not
receive an `acquire` handle from the unrelated table interface.

The paired implementation shares the **same first-turn provider response**
between `direct_adaptive` and `direct_masked`, then forks the second-turn
view. Each arm separately remeasures those first queries against the
deterministic native source and parent; both source executions and their work
count in their respective arm. Verify exact first-turn query and observation
equality in frozen records and archived replay. The provider first call is
charged once in the actual campaign ledger. If a later implementation uses
separate first-turn model samples, report its difference as descriptive; it
does not isolate outcome feedback. Record actual calls because an early
discrepancy may end either arm after the shared first call.

`direct_batch` is a finite plan and has no within-plan adaptation. The
compiled `ordinary` arm can in principle inspect receipts locally. Compare
their legal delivery, duplicate rate, valid distinct probes and fault yield;
do not call a batch that happens to work an adaptive learner. Fixed testing
has one fewer model call and remains the cost-aware ordinary rival.

Use the strongest already exposed small fixed pack before freezing new data.
Return 16's standards-informed comparator replaces the UTF-8 fixed queries
with one-feed boundary words `C0`, `C1`, `F5`, `FF`, `E0 9F`, `ED A0`,
`F0 8F`, `F4 90`, filtering public duplicates and filling any vacated slots
from the old fixed sequence. It retains the present LRU and SQLite packs.
It embeds no expected answers; the host measures each
query. On the old exposed parents it found the same three faulty episodes at
29 stop-first calls as the old pack, but its first failures were semantic in
three rather than one. That retrospective advantage includes an external
RFC 3629 prior and is not an equal-prior learned result. Freeze its exact
source and candidate sequence in the new dataset; retain the old pack in the
historical archive.

## Stages and decision rules

First run an offline interface check on the exposed archive and synthetic
continuation fixtures. It must check first queries, a required second distinct
query, legitimate stopping, duplicate accounting, typed error ownership,
masked fields and preservation of the original no-retry behavior. This check
is a release gate for the runner, not scientific data.

Then run the three-parent paid qualification under its own frozen budget.
Require valid direct-arm delivery on every contract, at least one actual
second-turn opportunity with a distinct legal proposal, and zero cases where
an investigator failure is labelled as a parent defect. If these checks fail,
retain all attempts and repair the interface in a newly versioned study. Do
not tune prompts or code and then append a continuation under the old freeze.
Qualification outcomes are never pooled into the diagnostic.

If qualification passes, run the separately frozen twelve-parent diagnostic.
Its maximum planned calls are 144: 12 parents, at most 60 unique investigator
calls and 72 repairs. The shared provider first call is counted once per parent;
both arms' native executions are counted. The
three-parent qualification ceiling is 36 planned calls.
These are allowances, not expected counts or invoices. The diagnostic has no
post-hoc arm or parent selection. Freeze all repair selections before opening
the screen and confirmation panels. The screen is diagnostic; inspect the
confirmation panel once after the freeze. Neither panel supports a claim
about new repository mechanisms.

The primary paired contrast is `direct_adaptive` versus `direct_masked` on
confirmation correctness across **all** frozen parents with the verified
shared first turn. Report its
per-parent difference and each contract's mean difference. Also report the
count of additional distinct legal second-turn measurements and verified
discrepancies. Report how many paired episodes actually reached a second
decision; a first-turn witness or stop offers no feedback intervention. The
second-decision subset is a prespecified mechanism description, while the
all-parent contrast is the primary intention-to-treat result. Compare both
direct arms with `fixed`, `direct_batch`,
`ordinary`, `repair_only` and the unchanged parent. A higher probe count is an
intermediate outcome, not success. If first turns are separate, use the
adaptive–masked contrast only as a descriptive diagnostic and make no
feedback-isolation claim.

There are only three mechanism families, so do not compute a case-row
significance test or present twelve parents as independent domains. Give
parent-paired totals, family-stratified values, complete observed ranges and
the exact selected/unchanged repair counts. Keep initially correct parents
in the denominator. A clean gain over `repair_only` suggests that new
evidence helped the repair path; a gain only over the unchanged parent is a
repair result. No performance threshold here can establish general transfer.

## Accounting and interpretation

For each arm record proposal slots, distinct legal native probes, duplicate
proposals, invalid proposals, source work units, selector or direct model
calls, repair calls, input/output/reasoning tokens, settled charge, unknown
charge, wall time, selected candidate and both panel scores. Attribute the
shared parent call once in lifetime totals, not once per arm. Unknown billing
is unknown rather than zero. Report native work units only within a source
family; SQLite statements and UTF-8 bytes are not fungible units. Preserve
failed outputs, unchanged repairs and regressions.

After this diagnostic, a positive feedback or finite-plan result justifies
a separately frozen study on changed client obligations with a persistent
ordinary tester and exact same-history controls. A fixed or repair-only win
means adopt the simpler procedure now. A null result is still useful: it
prevents a claim about memory or adaptive learning from being built on an
interface that has never delivered a second informative question.

Run `python scripts/analyze_progress_campaign.py <frozen-run-directory>`
after freezing and scoring to obtain parent-paired, contract-stratified
descriptive counts from the source-bound records. Run `python -m pytest
tests/test_progress_analysis.py` for its offline checks.
