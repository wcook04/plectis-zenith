# Fifteen deep returns: learning the decomposition

Historical research record. References to “current” or “next” describe this stage; see [today’s findings](../status.md).

**Decision:** make the decomposition of an investigation learnable. Treat its graph as a revisable theory of which distinctions, observations, computations and interfaces the work needs. A node can question its own boundary and propose a change to its caller, consumers, state, assumptions or next experiment. Useful evolution can split, combine, remove or specialize nodes; growth is not the objective.

This is a research direction, not an implemented reflective runtime or a new positive model experiment. We inspected all fifteen returns, their main arguments, critical code and saved evidence. All **769 manifest-listed payloads** match recorded membership, sizes and hashes. We did **not** rerun their simulations or test suites. Numerical results below remain **author-reported**, with source and argument inspection. No model calls were made in this assimilation. The [machine-readable receipt](deep-returns-20261014.json) binds the original archives and decisions. Earlier independently replayed experiments retain their separate [status](../status.md).

## The common mechanism

Several returns become one idea when read together: **experience can reveal a distinction that the current organisation loses, hides or makes costly to use.** Repair then changes that organisation, rather than repeatedly adjusting an answer inside it. Some cases require additional information or state; others need a more useful interface to computations the existing language already expresses.

The clearest example is return05. A caller discards the high byte of a two-byte length. Headers `0001` and `0101` both reach the helper as `01`, although the required answers are 1 and 257. No deterministic helper using only that input can answer both correctly. Seeing its caller and downstream obligation lets a node propose an input change. This is an exact information obstruction, checked by reasoning; the proposed context-aware model response has not been tested.

Return03 gives the temporal version. Two currently empty SQLite tables can require different next allocated keys because their histories differ. A learner acquires a watermark recurrence, then changes its lifetime after rollback defeats a globally persistent register. Return07 gives the compositional version: useful helpers are extracted from acquired end-to-end programs, without intermediate vectors supplied as training targets. Return13 closes another part of the loop: an acquired source model yields short histories and questions for calibrating related sources. **What was learned changes how the next learning problem is approached.**

Together: acquire a missing distinction; make it executable; use it to expose a reusable interface or design a better experiment; let later work reveal where it should be refined or retired. No return demonstrates this complete process with reflective language-model nodes. The parts are concrete enough to motivate that experiment.

An authored learning algorithm or hypothesis language does not erase genuine learning. Experience still determines source-specific recurrences, compositions or coefficients. Compiling the acquired object into ordinary code does not remove its value. The architectural question is whether explicit local context helps **discover, revise and reuse** it at lower total effort. Requiring graph syntax to have unique expressive power would be the wrong test.

## What to borrow from the broader system

The most relevant historical raw-seed idea is locally focused work with a selectively detailed connected neighbourhood. The worker sees what changes its local obligation: upstream information, downstream demands, alternatives and ways to inspect the underlying evidence. Later system theory describes compression of available choices, as distinct from merely shortening text. It treats abstraction as a lattice: a local failure may change an interface, theory or vocabulary, and a broad rule may need specialization.

Another useful principle is to seek one common explanation behind several symptoms, then judge it by observed behaviour. These are inspirations, not evidence that the private system already implements autonomous scientific learning. Original-source anchors and hashes remain in the local scout provenance; no private raw-seed corpus is copied into maintained documents.

Do not import a hierarchy of executive agents, a large ontology, or the private repository's governance machinery. Nor should every node constantly narrate itself. A validated arithmetic operation can remain ordinary code. Model reasoning is most useful where a boundary, assumption, explanation or next investigation is disputed. Sometimes the right result is no change, a narrower claim, or a smaller graph.

## A theoretical graph can do real work

The graph can begin with questions, candidate explanations and their dependencies before any program exists. A node might discover that its question is ill-posed, that two explanations make the same observed predictions, or that several failed approaches need a common lemma or observable. Its output can be a question, counterexample, proposed abstraction or experiment. Not every internal thought needs an immediate task-score improvement.

Distinguish **exploring a hypothesis** from **establishing its consequence**. An empirical claim eventually needs an observation that could disagree; a mathematical claim needs an argument or proof under explicit premises; a reusable procedure needs a later consumer. Internal coherence guides search but cannot supply missing external information. Speculative branches and temporarily regressing candidates can remain available without becoming accepted answers.

Keep three relationships intelligible: which computation consumes another's output; which observation supports or challenges an assumption; and which alternative or experiment remains worth considering. These need not become three frameworks or a compulsory edge taxonomy. A minimal proposal names a limitation, a concrete change, its expected consequence and a way to investigate that consequence. Names and interfaces are themselves revisable.

First-run improvement is possible. Pretrained knowledge and supplied context can expose contradictions, derive implications and build useful structure immediately. Observations can then force an acquired correction during that same run. This establishes neither cross-task accumulation nor an improving learning method by itself. For the latter, export just the changed investigation/update policy, remove old solutions and histories, and test acquisition on new problems.

## The next discriminating experiment

Start with a mechanism test of **context-informed structural revision**, using small source adapters or software semantics with independently specified outputs. Include information lost at an interface, missing historical state, a useful shared computation buried in prior solutions, and an irrelevant or stale abstraction. The byte example motivates the design; it must not be the sole memorisable test. Freeze different later cases and independent source/task pairs before proposals. This is not yet a production-value demonstration.

Compare:

1. **Fixed decomposition:** local implementations may change, but interfaces and state boundaries stay fixed. This identifies a structural obstruction; it is not the strongest competitor.
2. **Global ordinary agent:** a competent agent may refactor the whole program, add state/helpers, inspect evidence and design probes. This is the primary alternative.
3. **Contextual local revision:** a selected node sees its inputs, callers, consumers, failures and relevant choices, and may propose changes across its boundary. Not every node needs activation.
4. **Equivalent ordinary representation:** offer the same role/dependency information as code and contracts without special graph navigation. This separates useful information from the interface presenting it. A local-only context ablation can follow a positive signal.

All receive equivalent evidence, source access and total model/execution allowances. Charge retrieval, reflection, rejected proposals and probes. Ordinary code may retain shared abstractions, dispatch and state; flattening need not duplicate subgraphs. Fresh reconstruction with full history and replay of earlier structure on final evidence distinguish useful persistence from extra information. A cold/no-history snapshot separately tests acquisition beyond prior model knowledge.

Seek a causal trace: a limitation, a proposed change, its execution, and a later consequence the earlier structure could not supply. Score whole-task correctness, unsupported commitments, recovery, later construction effort and total cost. Neutralizing an intermediate can establish use; it does not prove unique semantics or architectural superiority. Evaluate source/task pairs, not correlated outputs as independent replications.

If this works, test whether the acquired model produces better subsequent experiments, then whether the update policy transfers without old solutions. If ordinary code ties, retain the acquired knowledge and prefer the simpler organisation. If both fail, inspect missing information, expressive capacity and search separately. More reflective prose is not the default repair.

## Prior art and claim boundary

Context-described nodes and self-editing agents are established research directions. [TextGrad's variable interface](https://textgrad.readthedocs.io/en/latest/modules/textgrad.variable.html) includes role descriptions, predecessors and contextual feedback. [ADAS](https://arxiv.org/abs/2408.08435) searches agent programs using an archive. [Gödel Agent](https://arxiv.org/abs/2410.04444) and the [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954) study self-modification. [Hyperagents](https://arxiv.org/abs/2603.19461) explicitly studies modifying the meta-level improvement procedure. Primary sources were checked for this conceptual overlap; performance was not independently replicated here.

Zenith's possible contribution is narrower and testable: **local contextual inference that discovers and revises useful distinctions and interfaces, then reuses them to make later investigation cheaper or more capable**. Neither originality nor effectiveness of that combined mechanism is established by this assimilation. Keep the freedom to discover a better mechanism.
