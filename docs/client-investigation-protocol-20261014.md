# Client investigation: retained procedure after a changed obligation

**Status:** prospective, authored within-family study. No provider call or target result belongs to this protocol yet. The current SQLite client tasks are an executable delivery pilot, not independent evidence of transfer to another project. The parent [Progress comparison](progress-protocol-20261014.md) tests new evidence and repair on native programs; this study asks whether an investigation learned on one client workflow helps characterize a later, changed client workflow.

## Unit and retained object

The unit is an opaque client implementation under a public behavioral contract. The development workflow is atomic batch import; the later workflow is account transfer. Both use caller-owned transaction state, failure injection, continuation and readback, so a useful question may need to run a sequence and inspect state after an error. The task host, not a model, measures the reference and candidate through native SQLite execution. The host retains every query, error, native work unit and result. Candidate source, implementation labels, held-out panel and hidden fault classification are unavailable to all investigator arms. Correct clients remain in the population.

After development investigation, the procedure arm may save one compact executable question policy. Its input is the public contract, legal query grammar, prior measured receipts and remaining allowance. Its output is a legal query or a stop decision. It may encode how to test interruption, transaction ownership, continuation and readback, including branches conditioned on measured outcomes. It must not contain a target answer, hidden implementation label, repaired code or target-specific expected output. Both preparation arms see the static transfer-family contract and full legal grammar before compiling, but no target ID, example, candidate result or hidden source; this is known-interface adaptation, not discovery of an unknown interface. The procedure and its scope/decline rule freeze before any transfer query. A model-authored target binding, if needed, is itself recorded and charged; host-authored semantic rescue is forbidden. A saved regression case or ordinary test generator is allowed in the rival arm and must be treated as a serious alternative, not renamed as a uniquely new representation.

The SQLite pilot is especially stringent because earlier PROGRESS returns already exposed rollback and caller-ownership faults, and a tiny fixed tester found both. Finding those same defects again does not show new knowledge. It establishes at most that a procedure is delivered, valid and able to choose a useful later question. A positive substantive claim requires an independently chosen client or implementation lineage with a genuinely changed obligation, frozen before seeing either arm's target results.

## Frozen comparison

Before inference, freeze source and task hashes; development/target task IDs and implementation lineage; legal query grammar; first public example; target-level protected panels; model, endpoint, reasoning and response schema; call and native-query ceilings; arm order; score code; and cancellation/budget paths. Use the existing budgeted provider and source snapshot routes. An amended interface starts a new version and preserves invalid attempts. No automatic retry or manual repair of a model output.

Each target arm receives the same public target contract and benign example. Procedure, ordinary code reuse and same-history fresh receive the same complete permitted development transcript; cold receives no history, and the fixed tester uses only its predeclared contract-based queries. The model-driven arms have the same six-query ceiling and one-query feedback cadence. The ordinary archive gets the same preparation allowance as the procedure arm and may retain ordinary executable tests derived from the transcript. Target queries are measured anew and charged to each arm. The primary comparison is:

| Arm | Retained development material | Target strategy |
|---|---|---|
| Retained procedure | Full transcript plus frozen executable policy | Invoke policy on target receipts; charge any target binding/model work |
| Same-history fresh (artifact ablation) | Same raw transcript and old measured answers, with the procedure removed | A fresh ordinary investigator chooses target queries; reconstruction calls are charged |
| Ordinary code reuse | Same transcript and one preparation call, equal to procedure compilation | Retain and execute the strongest ordinary reusable tester/code |
| Fixed tester | Public contract and a predeclared sequence | Run the same sequence, including follow-on recovery/readback |
| Cold ordinary | No development transcript | Investigate with equal target allowance |

The same-history fresh arm is the **artifact ablation**: it removes only the policy artifact while leaving the raw development transcript and old measured answers available. This tests whether the artifact itself changes later behavior. Ordinary code reuse is a separate, equal-preparation rival. A fixed tester or ordinary archive that ties or wins is a real null result for an architectural advantage. If the fresh arm reconstructs the procedure, charge its reconstruction calls and time; do not suppress that competence.

The pilot uses opaque batch-import implementations for development and opaque transfer implementations for targets, including correct clients and changed failure/continuation obligations. Do not select target bugs by inspecting the procedure's behavior. Group results by target implementation, not by query row. An externally sourced changed client, when available, needs a separately frozen stage and independent evaluator; do not pool it with this authored SQLite family.

## Observation and scoring

The executable study must preserve action grouping and order, SQL/call work, outer transaction state, before/after tables, errors, failure location, recovery actions and readback. A passing pre-error state is not enough to establish atomicity. A native answer can depend on where a call is split or resumed; never normalize two query sequences as equivalent without checking that assumption. Invalid, duplicate and no-op actions consume the declared slot; technical host errors are not semantic counterexamples.

Primary pilot endpoint: whether an arm finds a legal **witnessed reference/candidate state difference** on each opaque target within the query allowance. A model note alone is insufficient. Correct-client slots and stopping are efficiency controls; no finite no-witness run certifies a client as correct or scores model specificity. The protected finite panel measures the *client's residual behavior*, not the investigator's prediction accuracy or generalization. A finite pass supports only the tested scope. If repair is attempted, evaluate corrected target obligations and preservation of earlier successes separately; do not infer repair from detection.

The fixed pilot plan uses all five opaque batch clients for development and all five opaque transfer clients as targets. Per target and arm: six query slots, one query per feedback decision, at most six direct model turns or six restricted-program executions; each retained artifact gets one preparation call. There are at most 92 model calls in the whole pilot (30 development, two preparation, 60 target direct calls), a shared $2 hard ceiling and no retry. This matches feedback cadence across model-driven and executable arms; actual calls can be fewer after a witness or stop. Source hashes and SQL-count costs are recorded by the host but withheld from model prompts. Each public benign example's native cost is recorded once per opaque task and disclosed separately from arm-specific query work. Worker executions and elapsed time are counted alongside provider attempts and native work. The model/endpoint/reasoning setting and actual unit prices must be frozen by the run manifest before inference.

Report per-target paired outcomes, invalid deliveries, duplicate/invalid queries, semantic versus technical disagreements, reference/candidate SQL units, model calls and billed tokens/cost, preparation and target-stage costs, and protected-panel scores. Charge unsolved targets their consumed or capped allowance in cost comparisons. Publish both target-stage and full-lifecycle costs; the latter includes discovery, policy compilation, ordinary archive preparation, binding, all provider attempts and native execution. Query rows are correlated measurements within a target, not independent replications. Predeclare a practically meaningful target-level success or cost advantage before opening the panel; do not manufacture a positive subset after seeing it.

## Claim boundary and next gate

The pilot may establish working acquisition and delivery of a measured, source-bound investigation procedure. It cannot by itself establish a generally improved learning method: the workflow and fault family are authored, and an ordinary tester may express the same retained logic. An improved-learning claim requires a later comparison that holds the target solver fixed and tests a changed procedure learner against its earlier version on new discovery tasks, with empty and retained memory conditions and all acquisition costs counted. Publish a tie or failure with the same source-bound receipts as a win.
