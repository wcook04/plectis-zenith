# Kept experience: does a record of earlier misses help a model test new programs?

DeepSeek V4.1 Flash sees only a Python function's specification and chooses five inputs. Each input runs on the reference solution and on every hidden faulty solution of that problem; a different return value, a different exception, or no answer within one second where the reference answers counts as exposing that fault. The faults are mistakes real code models made: EvalPlus-released solutions from ChatGPT, CodeGen-16B and InCoder-6B that pass every original HumanEval test but fail at least one EvalPlus input (535 behaviour classes on 115 problems). The model's weights never change; the conditions differ only in the text placed before the specification.

The [protocol](protocol.md) was committed before any held-out call (`9b6c2b3`), with two dated addenda: experiment 2 (reasoning off), written after the main arms were scored, and a scoring-robustness rule applied to every arm. The [frozen inputs](frozen/) are the practice record, both rule lists the model wrote and the hash manifest.

## Results on 58 held-out problems (two runs each)

Share of hidden fault classes exposed, mean over problems; change against the tester shown nothing, paired by problem, with a 95% bootstrap interval and a sign test.

| Shown to the tester | Exposed | Change | 95% interval | Better / worse problems |
|---|---:|---:|---|---|
| Nothing | 69.2% | | | |
| Generic advice | 65.8% | −3.4 | −9.6 to +2.6 | 14 / 16 |
| **Practice record** | **77.0%** | **+7.9** | **+1.4 to +14.7** | **20 / 6 (p = 0.009)** |
| Rules v1 (model-written) | 68.4% | −0.8 | −7.3 to +5.8 | 15 / 14 |
| Rules v2 (revised on development misses) | 72.7% | +3.5 | −3.2 to +10.7 | 14 / 11 |
| Imagined faults | 68.3% | −0.9 | −7.4 to +5.8 | 14 / 17 |
| Imagined faults + record | 72.7% | +3.6 | −2.8 to +10.1 | 17 / 15 |
| Five random EvalPlus inputs (no model) | 42.8% | −26.4 | −35.0 to −17.6 | 12 / 45 |

**What the gain is made of (exploratory).** About half of the record's gain comes from very large inputs that make slow faulty programs exceed the one-second limit. Counting only wrong values and exceptions, the record still leads, 69.8% against 66.3%, but the interval includes zero (+3.5, −2.1 to +8.9; 19 better, 8 worse). On the 53 problems where both conditions supplied five valid inputs in both runs, the gain is +6.0 (−0.8 to +13.2), so part of it is the tester learning the argument format.

**Reasoning (experiment 2, pre-registered after the main arms).** With reasoning switched off, the tester shown nothing exposes 55.9%, and no form of experience helps (record 53.5%, rules 49.7% and 48.3%). With reasoning on, the rules shorten median reasoning (about 4,400–4,900 tokens against 6,400) and the record lengthens it (7,300).

**Context.** The five inputs the model chooses unaided match about 28 random EvalPlus inputs; with the record, about 47. The best five EvalPlus inputs chosen with hindsight expose 99.3%. On the 29 development problems the first rule list led by 16.5 points on a single run; the held-out run did not reproduce it. On mechanical mutants (12 held-out problems) the record exposes 80.8% against 63.0% (+17.9, +1.2 to +37.5).

**Cost.** 1,565 provider calls for $5.70 on one endpoint (`morph/fp8`): $1.09 for practice, development and the rule lists, $4.42 for the experiment 1 held-out run, $0.19 for experiment 2.

## Limits

One benchmark of short Python functions; faults from three code models released in 2022–2023; one tester model; problems weighted equally. EvalPlus inputs define the ground truth, so a fault no augmented input exposes is invisible here. The held-out problems were reused for experiment 2, so its result needs fresh problems to confirm. The protocol's prose named values and exceptions but the frozen scoring code also counted timeouts; both versions are reported above.

## Evidence and replay

- [`examples/kept-experience/`](../../../examples/kept-experience/): every reply with its reasoning (`replies.jsonl.gz`), the cost ledger, the fault population and the held-out score files.
- [`results.json`](results.json): every number above, generated by `scripts/build_kept_experience_results.py`.
- Re-score from the stored replies, with no model calls (needs HumanEvalPlus v0.1.10; executes sampled model code, so use a disposable environment):

```sh
python scripts/replay_kept_experience.py replay /path/to/HumanEvalPlus.jsonl
```

- Rebuild the fault population from the EvalPlus releases: `python -m research.kept_experience.natural <HumanEvalPlus.jsonl> <samples_dir> <out_dir>`; execution is memory- and time-bounded per process (`research/kept_experience/sandbox.py`).
