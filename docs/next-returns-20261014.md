# Eight next-round returns: what changes the research

The target is accumulated useful capability: after experience, the system can do later work that it previously could not, or can do it with less total effort. A growing archive can contribute to that. A changing graph, a changing program and an improving learning policy are different claims.

Eight returns were received and independently inspected: 01, 02, 03, 05, 07, 08, 09 and 10. The operator reports that 04 (investigation) and 06 (composition) failed to return. Their absence is not a scientific negative result. Original ZIP hashes, reproduction scope and adoption decisions are bound in the [custody receipt](next-returns-20261014.json). This pass makes no paid model calls and does not install the returned prototypes as one new runtime.

## The strongest combined idea

Retain both **a computation and the experiments that can expose its limits**. An experiment contributes more than an answer: it can identify a missing distinction, discriminate alternatives, or become a reusable challenge on a new source. A computation contributes more than a prediction: it can become a component of later work. Source bindings and explicit assumptions determine when either can be reused.

This suggests one small loop: try available procedures on the available evidence; obtain a useful measurement or independent challenge; identify whether the problem is missing information, a wrong representation, stale applicability or a wrong program; construct a better procedure when needed; and measure later usefulness. Lab, Oracle and Evolve remain names for the functions of this loop. Ordinary code, observations, tests and dependency records are sufficient to express it. A special graph or memory system must earn its place through improved behavior or cost.

The returns sharpen that proposal in four ways. First, code that is unnecessary now may become useful after new evidence, so present-answer equivalence is an unsafe deletion rule. Second, a useful contradiction can make apparent coverage worse, and a necessary intermediate repair can increase residual error. Search therefore needs to preserve useful alternatives without deploying every regressing candidate. Third, disagreement among current programs cannot expose an error shared by all of them; independent challenges remain essential. Fourth, a failure of one output does not automatically invalidate every output, but separately surviving fits do not establish a valid joint world either.

The missing step remains **acquisition**. Much of the new evidence comes from researcher-authored catalogues, abstractions, wrappers, controllers and schedules. These show that mechanisms can work under stated conditions. They do not show that our model discovers those mechanisms, representations or useful questions. The next research must locate exactly what experience supplies and trace it into a later capability. Ordinary code may embody genuine learning; the distinction is acquired versus supplied knowledge, not graphs versus code.

## Resolve the conflicts before merging code

**Partial reuse requires a warrant.** Return 02 permits state reuse after counter failure under a counter-only noninterference assumption, and recomputes from the full relevant evidence rather than keeping the old joint survivors. Return 07 instead evaluates each quantity against its projected family. This can be valid if the true quantity still belongs to that family and observations are correctly bound and stable. It does not follow from a surviving fit or from the learner's code having separate functions. Return 10's joint support remains appropriate when those weaker contracts are not justified. The open learning question is how the system acquires and tests the preservation warrant without knowing the private mutation.

**Observed correctness is not future equivalence.** Return 03 shows why pruning currently equivalent program bodies can destroy future learning. Return 10's small failure basis is explicitly relative to a fixed library. These are consistent: compress checks for a known inventory, retain original observations, and revalidate the index/basis after the inventory or semantics changes. Neither result justifies merging distinct computations permanently because their present answers match.

**A search state and a serving program have different acceptance rules.** Return 05 supplies a concrete bridge that a scalar-monotone repair path would reject. Return 08 explains why an investigation can have delayed value. A bounded search may retain regressing intermediates, while the selected serving program still obeys the deployment/evaluation contract. We need a rule that finds useful bridges from available evidence, not hindsight about the intended fix.

**A passing diagnostic is weaker than an identified guarantee.** Return 01's canary misses a second write path; return 07's narrow gate misses a behavior a longer fixed stress test finds. Both warn against treating one successful calibration as a universal certificate. Independence is about challenging assumptions or source paths, not merely asking another model or changing a random seed.

## What to change now, and what to defer

The research programme now prioritizes choosing a useful observable workload and obtaining a clear acquired-capability result. Mirror maintenance is a concrete lead; source adapters and other operational tasks remain alternatives. The task must offer a reason to learn rather than repeatedly execute the native source, and feedback must be available at its true cost. A new task is acceptable if it preserves the cumulative-learning question.

Preserve existing immutable runs, source code, observations, rejected candidates and graphs. Keep the existing provider and restricted executor. Use the returns as evidence and experimental designs; do not merge eight overlapping prototype libraries or install fifteen new modules. No new runtime behavior is claimed in this assimilation. Changes to repair search, binding-time compilation, component survival or investigation policy need explicit comparisons.

Defer an expanded campaign, a general ontology, compulsory graph routing, aggressive answer-equivalence pruning and a claim of improved learning policy. A larger disclosed family alone does not resolve the acquisition bottleneck. Neither does a perfect authored solver. A strong first result would show an informative failure causing a new computation or representation that helps with later externally specified work, against a competent archive, fresh construction and native/cached alternatives.

The next fifteen inquiries address useful tasks, new computation, learned state, shared blind spots, repair, validity, composition, memory, change, investigation horizons, learning-policy transfer, useful questions, a stronger organizing principle, decisive experiments and a single final system. They are competing explanations and design decisions to synthesize, not fifteen required components. Each can overturn the present hypothesis.

## Reproduction and claim boundary

The eight returned test suites contain 309 tests in total. Detailed command results, versions and exact-output comparisons are recorded in the custody receipt and packaged independent audits; test passage alone does not validate a learning claim. Original artifacts remain unchanged. Reproductions use disposable copies, Python 3.12.7 and SQLite 3.45.3, with no model calls.

Return 02's deterministic semantic outputs match; its trigger report excludes version/receipt-hash metadata from the cross-version comparison. Return 09's 41 tests and five core/input-dependent JSON reports match. Its optional seventy-source bank replay agrees on the aggregate winner and 24/24 score, but differs on 216 individual rows after nine worker terminations, so the full strict command exits nonzero. That optional replay is not fully reproduced and is not a new confirmatory experiment. The stronger fixed stress control for return 07 is an additional authored analysis on the exposed schedule, also not independent confirmation.

Earlier measured campaigns retain their original claims and costs in [status](status.md). No new model learning, graph benefit or recursive self-improvement is established by this pass. The gain is a sharper, reproducible account of which mechanisms deserve the next experiment and which apparent successes have simpler explanations.
