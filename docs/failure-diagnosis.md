# Failure diagnosis

The financial profile scores each frozen forecast against the later observation,
then reviews the original intermediate reasoning through six source lanes. The
[reasoning ontology](reasoning-ontology.md) defines the executable output schemas.

Oracle distinguishes evidence absent from the permitted packet, evidence
available but discarded, an unsupported inference, numerical-model error,
irreducible uncertainty, and no supported failure attribution. Every attribution
names a Lab node, cites a saved field, states a feasible test and records its
uncertainty. A wrong prediction alone does not establish a faulty reasoning step.

The subject index exposes Lab’s complete topology, effective instructions, stage contracts, original feeds, all nineteen reasoning records and hash-bound input reconstruction. Every Oracle reasoning node depends on this record. The
numerical difference tool preserves each prediction, realised value and error.
Lane reviews feed a combined account, attribution and critique. Later facts can
explain why a forecast failed; they cannot become evidence that the earlier node
was entitled to use.

Evolve selects one hypothesis and writes a reusable instruction for an existing
node. It stages that candidate without modifying source dossiers. A local replay
copies unaffected artifacts byte for byte and reruns the selected node and its
descendants. An empty-instruction replay controls for repeated execution. The
receipt names every frozen and rerun node and hashes the frozen artifacts.

A repaired old case is development evidence because its outcome influenced the
repair. A separate comparison freezes the instruction before running original
and revised programmes on the same later cutoff packets. Both commitments must
exist before outcomes are opened. Gains, regressions, no-ops and failed attempts
remain visible. A small comparison demonstrates this process, not general skill
or a causal explanation of the external market.
