## Working test reuse

DeepSeek V4.1 Flash produced two executable testers that ran unchanged on five authored account-transfer clients after acquiring experience on batch clients. Both found **three of four faults without target-stage model calls**. The ordinary reuse condition tied the retained-procedure condition; fixed tests found **all four**. Both generated programs return one constant probe and ignore feedback, consuming ten duplicate slots apiece. This is working delivery and reuse, not an acquired adaptive policy or independent transfer.

The working condition used **46 calls for $0.007117764**, including development and compilation. Two earlier conditions remain published: [v1 stopped](studies/client/client-investigation-20261014.md), and [v2 produced one invalid program and another stop](studies/client/client-investigation-v2-20261015.md). All three together used **133 calls for $0.019295552**. They share an inspected task family and were selected sequentially, so they are not independent replications. The later interface was available before compilation; model weights stayed fixed. [Full working-condition results, native work and replay](studies/client/client-investigation-v2-low-20261015.md).

Counterexample refinement now retains each new access history with its distinguishing continuation. This restores the observation-table rank-growth requirement in [Worrell's weighted-automata notes, Proposition 1, pp. 2–3](https://www.cs.ox.ac.uk/people/james.worrell/MA-learning.pdf). Its smallest queue example completes in ten source calls; all eight native configurations fit their finite challenges. A nonlinear counter also solves the smallest queue example more simply. The notes assume a global equivalence oracle; the finite challenges used here cannot establish general source equivalence. ## What the reviewed sources establish

[Predictive state representations (2001)](https://proceedings.neurips.cc/paper/2001/file/1e4d36177d71bbb3558e43af9577d70e-Paper.pdf) provide conceptual context for future-test probabilities under a known stochastic model. The weighted-automata notes provide the observation-table construction used by the separate deterministic learner. [ILF (CCS 2019)](https://doi.org/10.1145/3319535.3363230) learns a neural testing policy from symbolic demonstrations; [CoverUp (2025, v4)](https://arxiv.org/abs/2403.16218v4) uses an authored driver and measured coverage/errors to refine regression tests; [Voyager (2023, v2)](https://arxiv.org/abs/2305.16291v2) retains and composes an executable skill library. These are distinct precedents, not external confirmations of Zenith's results.

[STOP (COLM 2024, v3)](https://arxiv.org/abs/2310.02304v3) recursively improves a code-improvement scaffold. [Hyperagents (2026, v1)](https://arxiv.org/abs/2603.19461v1) edits task and meta-agent code and evaluates acquired improvement procedures; its stronger compounding comparison is statistically unresolved. Zenith has no acquired improver of this kind. ## Research decision

Use ordinary reusable code and fixed testing as the present baseline. The next research question is whether experience can select a useful **new** question on changed mechanisms at lower total cost than that baseline. Saving target model calls is insufficient when fixed tests catch more faults. The current contribution is a working, inspectable testbed and a reproduced learner repair; a general learning advantage remains unproven.

The [three-page paper](../paper/zenith.pdf), its [source](../paper/zenith.tex), [README](../README.md) and [read-only website](../site/README.md) present this current scope. The website renders the paper's paragraphs, table, citations and diagram from the manuscript rather than maintaining a separate summary. Every published client condition replays without inference, including a separately labelled cross-SQLite behavioral check. The revised paper also describes improvement of the improver and a possible mathematics connection as future directions. No new experiment or integrated-learning result accompanies this editorial update.

Two proposed controls are now explicit in the [programme](../program.md). Bounded tester refinement would use development evidence only, give ordinary reusable code the same allowance and retain one-shot compilation as a control. A future improver comparison would freeze the improver on identical valid starting solvers, select solver children using development cases, freeze the selected source hash and then open withheld evaluation. Acquisition, failed proposals and evaluation would all count. Reinvestment would be tested only after a useful frozen improver had been demonstrated. These are proposed protocols, with no new runtime result.
