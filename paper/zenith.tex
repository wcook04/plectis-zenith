\begin{center}
{\Large\bfseries Zenith: evaluating revisions to a reasoning graph}\\[4pt]
Will Cook \quad\textbullet\quad 12 October 2026
\end{center}

{\small\textbf{This is not financial advice.} This paper describes experimental
research. Historical examples and model outputs are not investment
recommendations and must not be used to make financial decisions.}

\hypertarget{idea}{}
\textbf{Abstract.} Zenith studies whether recurring failures in a multi-stage
language-model program can guide useful revisions. It records intermediate
outputs, diagnoses errors and compares one revision with the original on later
inputs. This edition prepares a mixed demonstration: real saved stock, ETF and
prediction-market inputs, synthetic macro and news, and recomputed calculator
summaries. The native graph loads the inputs and prepares its first reasoning
request. No completed forecast or learned improvement is claimed. We also
propose a controller that selects small prompt variations from context.

\textbf{1. Evaluation protocol.}
Nodes read supplied evidence or earlier outputs and produce records for later
nodes. \textbf{Lab} selects assets and forecasts from a saved information cutoff.
\textbf{Oracle} compares the frozen forecast with later observations and
proposes a diagnosis; \textbf{Evolve} proposes an instruction, context or
dependency change. The base language model stays fixed during comparison.

Collect runs with the graph held fixed. Group failures across sliding windows
and several widths, counting unique cases rather than overlapping windows.
Freeze one revision and compare it with the baseline on matched later cases.
Cases used to select a revision become development data for subsequent work.

\textbf{Data and cutoffs.}
The demonstration keeps real stock, ETF and prediction-market inputs unchanged.
Only macro and news are independently invented replacements; calculator summaries
are recomputed from the actual mixed inputs. Per-feed hashes and labels identify
this construction~\cite{demo}. Real payloads remain private pending publication
review. A packet can contain a current state or dated histories available at a
cutoff. Predicting a later state and predicting a path need different targets
and scores. Saved collection times do not verify every underlying availability
time, and historical inputs cannot exclude later knowledge in model training.

\textbf{Prior work.}
DSPy composes LM modules~\cite{dspy}; MIPRO optimises their instructions and
examples against a downstream metric~\cite{mipro}. These are direct precedents
for prompt optimisation. AlphaGo Zero~\cite{alphago} and autoresearch~\cite{autores}
motivated successive version comparisons. Zenith uses finite external histories;
this prototype establishes no forecasting advantage.

The Lab has 25 nodes: six feed artifacts and 19 reasoning operators.
Each miner is a feed-specific analysis step. Saved intermediate records let a
reviewer locate an unsupported claim and inspect the evidence it received.

\hypertarget{trace}{}
Diagnosis first asks what information was available:
\begin{center}\small
\begin{tabular}{@{}p{40mm}p{116mm}@{}}\toprule
Candidate failure & Question for the saved record \\\midrule
Evidence unavailable & Was the relevant information absent from the saved input universe?\\
Evidence not supplied & Was it in that universe but missing from the node's actual input?\\
Reasoning error & Did the node receive the evidence but draw an unsupported conclusion?\\
Execution failure & Did truncation, parsing or another runtime error prevent a usable output?\\\bottomrule
\end{tabular}\end{center}
Keep unresolved cases unknown. Research performed after the outcome can help
explain an event, but cannot become evidence the earlier run supposedly had.
A repeated failure motivates an intervention test; frequency alone does not
identify its cause.

\hypertarget{research}{}
\textbf{3. Proposed context-conditioned prompts.}
Each reasoning node would keep a fixed task, input scope, output contract and
work budget. A shared neural controller would read market-condition features
available at the cutoff and select small wording variations for that node.
We call its outputs \emph{prompt settings}: numbers in $[0,1]$ that index an
ordered catalogue of text variants. They are distinct from the controller's
learned numerical weights. This extension has not been implemented or tested.

A first implementation could search a small catalogue, following discrete
prompt optimisation~\cite{mipro}. A neural controller could instead learn
from measured configuration losses. Backpropagation would train that
controller; hard text selection and hosted LM calls provide no ordinary
end-to-end derivative. ProTeGi~\cite{protegi} and TextGrad~\cite{textgrad}
use verbal feedback as a gradient analogy. Such feedback can suggest a
revision, but is neither a numerical derivative nor proof of its benefit.
VIX and sentiment are incomplete context features, not a complete regime
classification. Later test outcomes must remain outside development.

\hypertarget{results}{}
\textbf{4. What the demonstration establishes.}
The preparation command reads two saved input directories. It copies the real
stock, ETF and prediction-market artifacts byte for byte, creates the labelled
macro/news examples without reading their originals, and executes the existing
calculator on the assembled inputs. The public manifest records source and
input hashes; the public examples contain only the invented replacements~\cite{demo}.

\begin{center}
\begin{tabular}{lll}
\toprule
Lane & Computation input & Public payload\\
\midrule
Stocks, ETFs & Real saved tables & Withheld\\
Prediction markets & Real saved input & Withheld\\
Macro, news & Authored synthetic examples & Included\\
Calculator & Derived from mixed inputs & Withheld\\
\bottomrule
\end{tabular}
\end{center}

Withholding a real payload from the website does not replace it in the actual
computation. Synthetic examples are not anonymised observations and do not
establish what happened in the historical market. The real-data source rights
and permitted downstream uses remain under review; source-code availability
alone does not settle those questions.

\textbf{Verified boundary.}
The reduced graph passes topology validation. Native Lab execution loads all
six artifacts and prepares the Seed request, where it awaits an agent response.
The preparation uses zero model calls. It produces no completed CP1 or CP2,
forecast, Oracle diagnosis or Evolve comparison. This is an executable input and
handoff demonstration, not a financial backtest. Historical measurements from
other configurations are not results for this one.

\textbf{Next evaluation.}
First fix an authorised data and model setup, with reliable observation clocks.
Complete Lab, then measure selection coverage, forecast error and cost under
fixed rules. Use the same fallback for unselected assets and a predeclared
score, such as quantile loss at fixed levels~\cite{scores}. Compare one revision
with the baseline on matched later cases. A selected subset can look accurate
while missing useful targets; selection and conditional prediction error must
both remain visible. Freeze the change before opening the comparison outcomes.

The proposed controller adds a further hypothesis: whether context-dependent
prompt choices outperform fixed prompts. Test it on later cases, including
regime changes, costs and regressions. A mixed-input demonstration cannot
establish forecasting performance using real macro/news, and a finite later
sample cannot establish reliability in every possible regime.
