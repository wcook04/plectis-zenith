\begin{center}
{\Large\bfseries Zenith: programs, experiments and useful memory}\\[4pt]
Will Cook \quad\textbullet\quad 14 October 2026
\end{center}
\hypertarget{idea}{}
\textbf{Abstract.}
Zenith retains executable programs, measured evidence and questions that can
expose a program's limits. A model proposes an investigation; the host executes
it against a source; measured discrepancies inform whole-program repair.
A separate controlled study tests whether acquired questions help later
learning beyond retaining the same measured answers. They reduce extension
queries in six matched-cache conditions, but ordinary separate programs remain
cheaper over the full acquisition. Transferring all learned questions into that
simpler architecture instead increases work in five of six conditions. Native
software experiments favor fixed investigation overall, while one acquired
question supplies an additional reproducible regression test.
These are bounded mechanism tests, not evidence of recursive self-improvement.

\textbf{1. Learn code and the questions that challenge it.}
The retained object is $(P,E,Q)$: a program, source-bound observations and
executable tests or distinguishing continuations. A useful addition must
improve later behavior or reduce the work required to acquire it. Cached
answers, acquired representations and better investigation procedures are
different possible contributions; each needs its own removal control.
A graph is one organisation of ordinary code and evidence. It may be revised,
bypassed or removed when a simpler implementation works better.

\hypertarget{lab}{}
\textbf{Locate the failure before growing the graph.}
A wrong output may reflect lost information, an incorrect update, an incorrect
readout of sufficient state, or a boundary absent from the observations.
The archived SQLite model, for example, retained pending inserts but omitted
them when reading allocation state inside an open transaction. More state was
not needed. A rows-only helper in another task really did discard history.
A local impossibility claim requires two different obligations under the same
\emph{complete} available input, including hidden state and caller context.
A node's account of its own limitations is a proposal, not such a certificate.

\hypertarget{oracle}{}
\textbf{One executable loop.}
Each investigator sees the public contract, whole parent program, examples and
its own measured receipts. It returns a query and, optionally, a compact
hypothesis about the obligation, suspected defect and useful change. The host
compares the native answer with the parent's answer. A repair can change any
function, interface or state; selection preserves every previously correct
measured case as well as the aggregate development result. Ties are retained
without being called improvements. All proposals and failures remain recorded.

A better program does not by itself establish a better learning rule. The
following studies separate these claims and charge the cost of getting there.

\hypertarget{evolve}{}
\textbf{2. Can a learned question be useful memory?}
Six programs acquired in an earlier DeepSeek study act as local teachers on
integer sequences. An authored exact learner fits rational transitions and
readouts. Its state coordinates ask what a particular program would return
after a particular continuation. Counterexamples add distinguishing questions;
matrices and access histories are then fitted again. The alphabet is the
integers $-8,\ldots,8$. The linear class, extraction algorithm, seed tests and
finite challenge generator are supplied, following established weighted
observation-table learning~\cite{weighted}.

For each of six declared conditions, acquire five teachers and add the sixth.
Both extension arms begin with the \emph{same byte-identical measurement cache}
and original seed anchor. One also retains acquired question coordinates;
the other starts from generic output questions. Neither receives an extra
anchor for the withheld teacher. Costs count actual new teacher executions.

Retaining questions saves 11.2--63.1\% of extension queries, beyond caching the
same answers. Yet separate ordinary modules require only 3071 executions in
total, less than every joint lifetime. The joint representation uses 16
coordinates versus 25 across separate modules; compactness does not imply
cheaper learning. Symbol, arithmetic and time counters remain separate in the
receipts rather than being conflated with query counts.

\textbf{Pursue the simpler alternative, and keep its negative result.}
A separately frozen follow-up transfers every unique learned continuation from
five ordinary modules into the sixth. Target caches are empty in both arms;
old outputs cannot become new target truth. Ordinary target costs are
$(258,622,447,803,336,605)$; transferred-question costs are
$(380,671,574,768,477,671)$. Only one of six conditions improves. All final
models pass their checks: the loss is unnecessary acquisition work. We did
not select a favorable subset after seeing these results.

\textbf{What is established.}
Independent replay reconstructs all acquisitions and counters: 77,865 new
queries, 30 exact certificates and 18,432 later outputs for the first study;
6,612 queries, 12 certificates and 1,536 later outputs for the second.
Audit executions are separate from the original acquisition costs. Certificates
prove equality on every finite word to the supplied rational linear reference;
they do not prove that an unknown external source belongs to that class.
Both follow-ups use zero new model calls. A stronger-prior fitter of the known
finite source family also needs no new teacher queries after earlier calibration.

These are six correlated conditions on the same archived programs, selected
after an earlier positive return. They establish a narrow useful-memory
mechanism and its limits, not independent domain replications, an improved
general learner or a new automata-learning theorem.

\hypertarget{results}{}
\textbf{3. Model-generated investigation on native software.}
The live study uses authored contracts for SQLite allocation across
transactions, LRU cache counters and incremental UTF-8 decoding. Two fresh
parents per contract receive eight public examples. Each parent is compared
with ordinary adaptive investigation, investigation prompted to diagnose local
obligations and boundaries, and eight fixed boundary/prefix tests. Correct and
invalid parents remain included. Generated policies receive the same whole
code and evidence; there is no privileged graph engine.

Each investigation has eight slots and stops at a verified discrepancy.
Invalid and duplicate queries consume slots. All arms receive repair, even
without a witness, so a repair gain alone does not establish investigation value.
Generated policies cost one extra model call. Selections freeze before two
48-case panels per parent. Valid-probe counters exclude partial native work
before query rejection; rows are not independent mechanisms.

Ling3.1Flash on a pinned DeepInfra endpoint completed 36 calls for
\$0.03205644. On screening, the unchanged parent, ordinary, diagnostic and
fixed arms scored 218, 218, 224 and 241 out of 288. On confirmation they scored
216, 216, 218 and 239. Fixed testing found one semantic and two execution
failures; ordinary found one semantic failure; diagnostic found none.
Its small repair gain therefore does not demonstrate useful investigation.
Two UTF-8 parents had runtime errors despite valid syntax. Fixed repair improved
one; measured-case preservation did not prevent a later-case regression in the
other. This pilot favors the simpler fixed tester, not graph-aware prompting.

\textbf{One useful acquired question.}
An ordinary policy proposed UTF-8 bytes \texttt{[224,128]}; the source rejects
this overlong prefix, while a parent incorrectly keeps it open. Its accompanying
claim that this encodes NUL is false. A post-hoc check reuses the exact test
against both exposed UTF-8 parents and both fixed repairs: all four fail it.
On one parent/repair pair, all eight fixed queries find no semantic discrepancy;
they do find execution errors. Retaining this question adds a regression test,
not a demonstrated cross-mechanism learning policy. Its policy acquisition cost
\$0.00090378 and one native probe; including the shared parent costs \$0.00200028.

All five separately frozen studies total 79 attempted calls and \$0.11472222
known reported charges, plus one unresolved charge. Failed constructions,
including a reasoning-limit delivery failure and a storage interruption, retain
all paid outputs and have no protected scores. Exact receipts are in the repository.

\hypertarget{research}{}
\textbf{Contribution and next test.}
The research target is selective reuse of questions that reveal when state,
readout or decomposition must change. The positive memory comparison and
acquired regression motivate it; cheaper ordinary programs and failed transfer
constrain it. A next test must demonstrate lower full acquisition cost on changed
client mechanisms against an ordinary tester with the same earlier experience.
That benefit remains unproven.

Program generation~\cite{pal}, reusable skills~\cite{voyager}, library
learning~\cite{dreamcoder} and weighted-automata learning~\cite{weighted}
are prior art. These experiments do not establish a new general learning method.
The repository preserves source archives, original outputs and per-case outcomes.
