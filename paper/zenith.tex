\begin{abstract}
Zenith evaluates changes to a reasoning graph using dated inputs, native output
contracts and complete paired forecast support. Its executor binds runs to
source, graph, policy and provider identities; diagnostics distinguish recorded
failures from hypotheses about their cause. A proposal compiler can change one
node-policy field for controlled replay. A historical price-only study compared
one manually frozen persistence/scale rule with a model baseline over 20
August and five later October 2015 dates. On the later dates, candidate mean
relative price error was 0.8875\%, versus 0.9966\% for the model baseline and
1.0453\% for no change. On development dates, no change outperformed both model
policies. The 100-call study demonstrates pipeline feasibility and a descriptive
intervention comparison. Previously examined history, a modern model and limited
support prevent claims of prospective accuracy, learned improvement or novelty.
The learning question is whether measured development feedback produces a
forecast-node skill that improves later decisions over a frozen competent base
and equally budgeted proposal controls.
\end{abstract}

\section{Question and scope}

The intended system answers three questions. What should be forecast from
information available at issue time? What happened at the declared horizon?
What does the recorded attempt suggest changing? The first is a forward
reasoning task, the second a measurement task, and the third a diagnosis and
learning task. Price error alone cannot answer the third: a miss can reflect
unavailable information, restricted context, an unsupported inference, response
variation or an unpredictable event.

Zenith is a standalone extraction of an existing Lab--Oracle--Refinement system.
The original Lab combines stock and ETF prices, macro observations, news and
other feed lanes. Reasoning nodes interpret the supplied evidence through
instructions and typed output contracts; they can consider competing
explanations rather than execute a fixed indicator rule. Lab emits a thesis
checkpoint (CP1) and forecast checkpoint (CP2); Oracle resolves later observations
and critiques the frozen attempt. A retained dossier runner and a newer
reflection/cohort route implement different revision paths.

Graph-based reasoning is established prior art \citep{got2024}. The local
question is whether measured development feedback can improve a persistent
reasoning skill on later evidence under controlled replay. The completed study
uses a three-node price-only replacement, with one manually frozen skill rule.
It establishes execution and comparison boundaries; it does not test the full
multi-source graph or answer the learning question.

\section{Implemented mechanism and its guarantees}

\subsection{Native execution and evidence boundaries}

A node declares dependencies, instructions and an output schema. A reasoning
policy can add a short skill rule, set nonnegative incoming-edge weights or
limit context characters. Base instructions and output contracts remain
binding. Canonical artifacts are retained; context views contain full
artifacts, declared excerpts or omission markers. Receipts record source
hashes, retained characters and missing dependencies.

Declared edges are scheduled inputs. Effective requests also contain injected
contracts, temporal substitutions and configured context. Agent-provider
handoff packets retain complete prompts; the paid adapter records prompt hashes,
and engine attempt sidecars retain response text with at most 4,000 prompt
characters. A graph path therefore directs inspection without proving actual
model consumption or causal responsibility. Native output validation applies
to both paid responses and imported agent responses. Paid cohorts require the
same requested provider endpoint in both arms and check returned provider
identity against its catalog binding.

Observation time, first availability and acquisition time are distinct. Forward
evidence must belong to the subject-side class and have declared availability
no later than the issue. Unknown availability remains uncertain. Conservative
historical release rules do not authenticate publication clocks or price
vintages. Later truth is separated from forward execution.

The conditional Lean model proves composition when the constituent skills
satisfy their assumed relations, and expresses availability and rank-based
acyclicity constraints. The Python checker verifies declared ports, evidence
classes, source hashes and finite ranks. Neither establishes that a
natural-language skill implements its relation, that a timestamp is authentic,
or that the forecast is accurate.

\subsection{Measurement and proposals}

Each forecast names its target, horizon, issue and target prices, basis and
currency. Before maturity it is pending; missing or incompatible truth is a
data gap. For issue $i$, fixed target set $S_i$, predictions $q_{is}$ and positive
realized prices $y_{is}$, the cohort loss is
\[
 L_i=\frac{1}{|S_i|}\sum_{s\in S_i}\frac{|q_{is}-y_{is}|}{y_{is}},
 \qquad L=\frac{1}{n}\sum_{i=1}^n L_i.
\]
Targets are averaged within issues, then issues receive equal weight. Complete
comparison requires every included arm to have the exact frozen issue/target
support. Partial runs expose coverage without aggregate, per-issue or paired
scores. Complete receipts retain $L_i^{\mathrm{candidate}}-
L_i^{\mathrm{baseline}}$; negative values favor the candidate.

This is a point-price loss, not a trading return. No-change and past-one-session
momentum use the same support and loss. For positive outcomes with finite
inverse moment, absolute percentage error elicits an inverse-price-weighted
median, generally distinct from a conditional mean \citep{gneiting2011}.
Current instructions ask for a target price without naming that functional.
Any subsequent change to the elicited quantity or loss must be declared before
execution, rather than rescoring the existing study opportunistically.

Diagnostics bind artifact presence, validator rejection and context-delivery
conditions to recorded bytes and receipts. Missing or unbound evidence stays
unknown; observer failure cannot change cohort acceptance. A large final error
can select a trace for inspection but cannot certify missing data, data-access
failure or faulty reasoning as its cause. A hindsight reviewer may inspect
realized outcomes and later news to form a hypothesis. Its record must separate
checkable defects, relevant information available before issue but omitted,
post-issue events and unresolved explanations. Published explanations or
reviewer labels supply no causal ground truth. Only admissible pre-issue evidence
may enter a repaired forward run; its benefit needs a new measured comparison.

The reflection route binds development membership, feedback and selected node
artifacts plus available agent-provider exchanges. It does not consume all
paid debug sidecars; without a handoff packet the selected input prompt is
unavailable. An agent supplies a hypothesis and intervention. The compiler
checks the measured baseline, changes one skill rule, context budget or edge
weight through the policy validator, and records before/after identities.
Compilation neither executes nor accepts the candidate. An input intervention
needs a separately declared acquisition/ablation protocol. Coupled changes can
be tested through baseline/A/B/A+B replay; single-field changes have no general
optimality guarantee.

\section{Completed historical experiment}

\subsection{Fixed protocol and provenance}

The experiment uses StockNet price evidence \citep{stocknet2018}, with AAPL,
MSFT and GOOG fixed throughout. It supplies 20 past exchange sessions of OHLCV
and predicts the next exchange-session close. Development contains the first
20 common mature August 2015 issue dates; later assessment contains the first
five October dates. The native cohort freezes candidates, inputs and source
identities, separates split membership by calendar week, checks the declared
one-day embargo, and seals final assessment before opening its truth.

Both arms use the same three-node graph, model, provider and 24,000-character
context caps. Their sole difference is one CP2 skill rule: use current close as
a persistence prior, separate direction from move size, and shrink movement
toward zero when past-return scale evidence is weak, while preserving target
and grounding requirements. This rule was manually fixed before development
scoring, not generated by measured feedback. The baseline and candidate policy
identities are frozen in the cohort at prepared source revision
\code{01522cc}, hash prefix \code{bd5224387591}; full identities are in
\code{paper/study-evidence.json}.

The August outcomes had been exposed in an earlier flat-input study, and the
October dates had been examined in deterministic benchmark work. This
freeze supplies a controlled historical comparison, not a pristine holdout.
The modern model may also encode historical outcomes. Valid input timestamps
cannot remove pretrained look-ahead knowledge; anonymization controls can test
some effects without proving absence of memorization \citep{glasserman2023}.

Four compatibility pilots used 1 July 2015, excluded from the study. Nova and
Qwen responses failed length or reference validation; an unpinned DeepSeek
request returned HTTP 429 without usage or known charge. An audited recovery
preserved that failed attempt and reservation. A fresh DeepSeek request through
\code{deepinfra/fp8}, reported as DeepInfra, completed both reasoning nodes.
These six attempts yielded five responses and USD 0.004173065 in known charges.
Acceptance measures contract compatibility, not forecast accuracy.
\code{paper/calibration-evidence.json} and \code{paper/README.md} retain all
pilot outcomes, tokens, costs and implementation-hash matches; manifests record
no Git HEAD, so matches do not establish a unique executed revision.

\section{From a manual intervention to measured learning}

\subsection{Closest prior art and originality boundary}

QuantAgent's 2024 writer/judge loop retrieves experience, while an outer
market-data evaluation retains signal code, scores and feedback
\citep{quantagent2024}. ATLAS's Adaptive-OPRO updates static trading instructions
from prompt--performance history and recent outcome summaries while protecting
run-time inputs and interfaces \citep{atlas2026}. These precedents already
connect financial outcomes to persistent program or instruction changes.
Their alpha-factor and portfolio evaluations differ from the point-price loss
in Table~\ref{tab:results}; adjacent windows under different prompts do not
isolate the causal effect of an edit.

Trace propagates executed subgraphs and output feedback to trainable
parameters; OptoPrime proposes prompt, code or numerical updates
\citep{trace2024}. GEPA reflects on execution feedback and searches prompt
candidates \citep{gepa2025}.
Zenith presently compiles a reviewed node-policy intervention for native replay.
It does not implement either optimizer or unrestricted generated programs.
A skill change on a fixed graph is policy adaptation, not learned topology.
Dated admission, diagnostics and frozen comparison are the local implementation
focus; no new learning algorithm or established novelty is claimed. Reviewed
versions, software pins and broader comparisons remain in the source manifests,
rather than forming a citation inventory here.

\subsection{Controlled routing validation}

A separate deterministic benchmark composes the real context-policy owner with
a Decimal split-adjusted-price calculation and an independently implemented
Fraction oracle, without model calls. Across seven scenarios, a finite selector
scores unchanged policy and one-edge restorations witnessed in omission receipts
on 20 training cases; unchanged wins ties. The selected policy is fixed before
64 assessment cases with disjoint price/factor ranges are generated. Execution
accepts only sources and cutoff, rejects oracle labels, validates policy hashes
and preserves canonical inputs. Restoring the relevant split edge yields
64/64 contract-correct numeric answers (absolute tolerance $10^{-25}$), versus
0/64 for unchanged or irrelevant-edge restoration. Absent, future and conflicting
sources yield 64 correct abstentions and zero numeric answers each; healthy and
irrelevant-omission controls retain unchanged policy and 64 correct answers.
A faulty arithmetic operator stays wrong in all 64 cases under every routing
arm. Restoration increases delivered context, so this establishes no fixed-budget
efficiency. Published seeds, constructed faults and a restricted candidate set
make this integration/control validation, not an LLM skill-learning result,
causal discovery or financial forecasting evidence. The source-bound receipt is
\code{docs/repair-controls.json}.

\section{Limits and reproduction}

The completed result establishes native execution and a bounded historical
intervention comparison. It does not establish automatic credit assignment,
causal diagnosis, generalization of a learning procedure, usefulness of the
full Lab graph, market efficiency or profitability. Context restrictions,
missing evidence and reasoning can interact; an intervention measures
conditional sensitivity without uniquely identifying the original cause.
A modern model's stored knowledge, previously inspected windows, serially
related dates and three selected assets limit broader interpretation.
Generation and selection are fitting \citep{cawley2010}; a later learning study
must freeze proposals before outer assessment and disclose lifetime exposure.
An unchanged-rule repeat estimates model variation; a feedback-free proposal
control distinguishes feedback value from making another proposal. Neither is
present here. Repeated search also needs dependence-aware uncertainty over its
full comparison family, for which White's Reality Check is one framework
\citep{white2000}, not a statistic implemented or estimated in this study.

Planning for a later paid learning study paused after source audits found
sparse AAPL news and incomplete price coverage despite broad date ranges.
TraderHarness is the proposed multi-session panel from February 2023 onward,
subject to price-basis, corporate-action and complete-support checks.
Unknown-vintage fundamentals are excluded; day-only announcements require
conservative availability. This selection, documented in
\code{docs/data-selection.md}, supplies no new forecast or learning results.

The repository contains executor/schema source and text-free evidence
projections, not redistributed market text or private provider packets.
Candidate code is trusted local code; the runner is not a security sandbox.
Client-side reservations and reported usage do not guarantee provider billing.

The source-owner map is in \code{paper/README.md};
\code{docs/reproducing.md} owns environment and offline checks. Source and
finance manifests retain primary versions, software pins and adoption decisions.

From an editable source checkout, \code{python -m zenith validate} and
\code{python -m zenith plan lab} inspect the authored graph without inference.
The paper exporter reads existing receipts without evaluating, selecting or
sealing. Its validation accepted the actual complete phase reports and rejected
copied missing-support, altered-loss and invalid-selection probes while
preserving the original artifacts. Every measured claim must bind source,
inputs, graph/policy and model/provider receipts; a code citation alone cannot
reproduce the comparison.
