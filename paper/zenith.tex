\begin{center}
{\Large\bfseries Zenith: programs, experiments and useful memory}\\[4pt]
Will Cook \quad\textbullet\quad 15 October 2026
\end{center}
\hypertarget{idea}{}
\textbf{Abstract.}
Zenith retains executable programs, measured evidence and questions that can
expose a program's limits. A model proposes an investigation; the host executes
it against a source; measured discrepancies inform whole-program repair.
Two acquired testers run unchanged on five authored SQLite clients and detect
three of four faults without target-stage model calls. Ordinary code reuse ties
the retained-procedure condition; fixed tests detect all four. The complete
DeepSeek V4.1 Flash run costs \$0.00712. A separate learner repair preserves the
history witnessing each new distinction, but a generic control remains cheaper.
Earlier memory experiments likewise distinguish a useful question from an
advantageous learning architecture. These reproducible engineering results do
not establish selective transfer, recursive self-improvement or a general
advantage over ordinary testing.

\textbf{1. Learn code and the questions that challenge it.}
The retained object is $(P,E,Q)$: a program, source-bound observations and
executable tests or distinguishing continuations. A useful addition must
improve later behavior or reduce the work required to acquire it. Cached
answers, acquired representations and better investigation procedures are
different possible contributions; each needs its own removal control.
A graph is one organisation of ordinary code and evidence. It may be revised,
bypassed or removed when a simpler implementation works better.

\hypertarget{lab}{}
\textbf{Locate the failure before growing the graph.}
A wrong output may reflect lost information, an incorrect update, an incorrect
readout of sufficient state, or a boundary absent from the observations.
The archived SQLite model, for example, retained pending inserts but omitted
them when reading allocation state inside an open transaction. More state was
not needed. A rows-only helper in another task really did discard history.
A local impossibility claim requires two different obligations under the same
\emph{complete} available input, including hidden state and caller context.
A node's account of its own limitations is a proposal, not such a certificate.

\hypertarget{oracle}{}
\textbf{One executable loop.}
In the native repair study, each investigator sees the public contract, whole
parent program, examples and its own measured receipts. It returns a query and, optionally, a compact
hypothesis about the obligation, suspected defect and useful change. The host
compares the native answer with the parent's answer. A repair can change any
function, interface or state; selection preserves every previously correct
measured case as well as the aggregate development result. Ties are retained
without being called improvements. All proposals and failures remain recorded.

A better program does not by itself establish a better learning rule. The
client pilot therefore freezes a tester before later client execution and
compares it with ordinary reusable code, fresh investigation and fixed tests.
The public target interface is supplied during acquisition; the client programs
and measured target outcomes are withheld. This tests reuse on a known task
family, not discovery of an unseen interface. We charge the cost of getting there.

\hypertarget{evolve}{}
\textbf{2. Preserve the experience that justifies a new state.}
A continuation asks what a source will return after more actions. Two histories
can have the same present output but different future consequences. An authored
rational-linear learner uses measured answers to selected continuations as
state coordinates, then fits transition and readout maps. This follows ordinary
weighted observation-table learning~\cite{weighted}; the model class and
extraction procedure are supplied, not invented by a language model.

\textbf{A reproduced learner defect.}
The earlier implementation could keep a newly distinguishing continuation while
discarding the access history that witnessed it. The next fitting step then
lacked the independent evidence needed to represent that distinction. The
maintained implementation retains both. It also initializes from a nonzero
finite challenge when the empty word and one-symbol observations are all zero.
A failed fit must not be interpreted as proof that the source needs a richer
representation: the learner itself may have lost its witness.

The smallest reproduction observes a queue with capacity four, receiving the
same unit input repeatedly. Its output is $\min(n,4)$ after $n$ inputs. The
repaired learner uses ten source calls, fits five rational-linear coordinates
and agrees on lengths 0--32. That coordinate count is relative to the imposed
linear class. One nonlinear integer counter with update
$c\leftarrow\min(c+1,4)$ is simpler. The example demonstrates a concrete
algorithm repair, not discovery of an optimal representation.

\hypertarget{trace}{}
\textbf{Native checks and an ordinary rival.}
We adapt eight inspected fixtures: three bounded queues, two LRU capacities,
incremental UTF-8 and two SQLite allocation modes. Both conditions use the
same authored integer alphabet and finite challenge generator. The default
refinement is compared with a generic bank of one-symbol questions; that bank
uses no earlier task experience. Both complete all eight fits.

The generic control saves sixteen calls on one queue and ties the other seven.
There is no learned-memory advantage in this comparison. Later finite panels
also reveal residual error: UTF-8 scores 4,903/4,913 on length-three words;
SQLite rowid scores 190/192 and AUTOINCREMENT 191/192 on lengths 16--32.
Other fixture/panel combinations pass. Acquisition costs exclude later audit
executions. These eight configurations are an inspected diagnostic workload,
not eight independent applications or universal equivalence certificates.

\textbf{What remains of the earlier memory result.}
A separate study of six previously acquired program teachers retained the same
measurement cache in both arms. Keeping acquired questions reduced extension
queries by 11.2--63.1\% in six declared conditions. Yet acquiring separate
ordinary modules cost 3,071 source executions, below every joint lifetime
(5,427--5,698). A frozen follow-up transferring every learned suffix into the
simpler learner cost 3,541 versus 3,071 and hurt five of six targets. Exact
certificates there concern supplied rational-linear references, not arbitrary
native sources. These earlier populations and costs are not pooled with the
new eight-fixture diagnostic.

A question can be useful memory without every representation or transfer rule
being worthwhile. The next mechanism must select questions that pay for their
acquisition and preserve the evidence needed to use them.

\hypertarget{results}{}
\textbf{3. Working test reuse and its limits.}
Five authored SQLite batch clients supply development experience. A model
compiles a retained investigation procedure and an ordinary reusable tester;
both then run unchanged on five account-transfer clients, four faulty and one
correct. Each arm has six query slots per client and stops at a host-verified
reference/client discrepancy. Invalid and duplicate queries consume slots.
All target executions finish before a separate 400-case client panel opens.

Both compiled programs repeat one constant query and ignore feedback. Each
spends ten slots on duplicates. Their tests miss a partial-debit fault that
the fixed tester exposes. The result is working code reuse, not an adaptive
policy advantage. The task family was inspected during engineering; supplied
interfaces, shared clients and sequential condition selection preclude an
independent-transfer or statistical-significance claim.

DeepSeek V4.1 Flash, pinned to Morph, used 46 calls for \$0.007117764,
including development and compilation. Development plus procedure acquisition
costs \$0.001148298; development plus ordinary preparation costs \$0.000981024.
These alternatives share the same development cost. Study probes, public
examples and later checks total 467 reference and 467 client executions.
Two earlier versions produced stopping or invalid testers. All three versions
remain published: 133 calls and \$0.019295552. The working condition requests
low reasoning and a larger output allowance; the provider reports zero
reasoning tokens. Its success cannot be attributed to reasoning alone.

\textbf{Separate investigation diagnostic.}
On twelve parent episodes from SQLite, LRU and UTF-8 contracts, repair without
new investigation improves confirmation from 259/576 to 365/576 answers.
Fixed testing scores 364, compiled investigation 354, a direct batch 339,
feedback-aware two-turn requests 343 and outcome-masked requests 331.
The paired feedback gain is twelve answers on one parent; eleven parents tie.
Only five pairs reach a second decision. Eleven parent programs are unique,
but there are only three authored mechanisms; case rows are not independent
replications. No investigation arm beats repair alone. Ling3.1Flash on DeepInfra
uses 130 calls for \$0.12982944. Separate qualification, failed host admission
and a funding-only continuation retain their own receipts; no failed attempt
is erased or counted twice.

\hypertarget{research}{}
\textbf{Contribution and next test.}
The open target is selective reuse of questions that pays for its acquisition
on changed mechanisms, beyond an ordinary tester with the same experience.
LLM testing with feedback~\cite{coverup,testgen} and reusable skills~\cite{voyager}
are prior art. Our current contribution is a repaired learner, executable
comparisons and inspectable negative controls, not a new general learning
method. Original prompts, replies, failures, sources and offline replays are public.
